# JMeter Load Testing - Summary Report  

## Обзор тестирования  

Проведено нагрузочное тестирование Spring Boot приложения-калькулятора с использованием Apache JMeter. Тестирование включало:  
- Тестирование одного пользователя (baseline)  
- Тестирование высокой нагрузки (1000 пользователей)  
- Определение максимального количества одновременных пользователей (500, 1000, 5000)  

## Параметры тестов  

### Single User Test  
- **Пользователи**: 1  
- **Ramp-up**: 1 секунда  
- **Циклы**: 5  
- **Всего запросов**: 20 (10 POST + 10 GET)  

### High Load Test  
- **Пользователи**: 1000  
- **Ramp-up**: 10 секунд  
- **Циклы**: 5  
- **Всего запросов**: 10000 (5000 POST + 5000 GET)  

### Max Users Test  
Использованы те же параметры, что и в High Load, с различным количеством пользователей:  
- **500 пользователей**: 5000 запросов (2500 POST + 2500 GET)  
- **1000 пользователей**: 10000 запросов (5000 POST + 5000 GET)  
- **5000 пользователей**: 50000 запросов (25000 POST + 25000 GET)

## Выводы  

**Вывод:** Приложение стабильно работает до 1000 одновременных пользователей без ошибок.  

- ✅ **500 пользователей**: Отличная производительность (19 мс среднее время ответа)  
- ✅ **1000 пользователей**: Приемлемая производительность (845 мс среднее время ответа), нет ошибок  
- ❌ **5000 пользователей**: Критическая нагрузка (8.35% ошибок, 11+ секунд время ответа)  

**Производительность по эндпоинтам**  

- **GET /api/calculations**: Показывает сопоставимую или даже немного худшую производительность при высоких нагрузках по сравнению с POST  
- **POST /api/calculations/compute**: При низких нагрузках медленнее, но при высоких нагрузках может показывать лучшую производительность  

**Пропускная способность**  

- Максимальный throughput достигается при ~350 req/s  
- При увеличении нагрузки с 1000 до 5000 пользователей throughput не увеличивается, что указывает на достижение предела пропускной способности
